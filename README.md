# FuriPop — X 與 YouTube 日文假名助手 v0.3.7

支援 X 與 YouTube 觀看頁的日文讀音，保留不改寫平台原文、避免影響版面的產品方向。

- 讀音浮窗的文字可以直接反白；較長內容可在浮窗內捲動，按 Esc 關閉。鍵盤與螢幕閱讀器支援仍需在實際輔助技術上驗證。
- 已知限制：不同裝置同時修改自訂詞典時可能互相覆寫，建議避免同時編輯；語言判定和人名、多音字讀音仍可能錯誤。

反白日文長文時，讀音浮窗會限制高度並提供捲動；浮窗設有供輔助技術使用的即時狀態，實際播報效果尚待驗證。浮窗也能用 Tab 聚焦、以 Escape 關閉。

## v0.3.7：直接拖曳字幕

- 可直接拖動 FuriPop 可見字幕，位置在同一影片換句時保留，導覽至其他影片時重設。這是擴充功能的顯示位置，不會修改或儲存 YouTube 原生字幕位置；切回原生字幕時會回到原生位置。
- 隔離 Edge 模擬測試涵蓋水平和垂直拖曳、重複拖動、換句後位置及播放器控制，仍需以真實 YouTube 字幕驗證。

## v0.3.6：穩定性與發布整理

- 播放器尺寸變化時重新定位字幕；同時出現多個字幕視窗時保留 YouTube 原字幕，避免錯誤合併位置。特殊多視窗暫不加假名，真實 YouTube 字幕仍需驗收。
- 修正開關設定儲存失敗時介面仍顯示成功；加入開關名稱與鍵盤焦點樣式。
- 隔離瀏覽器測試結束或啟動失敗後清除其 profile。執行 `powershell -NoProfile -File scripts/package.ps1` 產生僅含執行時檔案的套件，保留完整詞典並逐檔核對雜湊。
- 自訂詞典與開關使用 `chrome.storage.sync`，依使用者瀏覽器同步設定可能跨裝置同步；文章和字幕文字在本機分析。

## v0.3.5：字幕對齊與持續更新

- 改善字幕行距，降低模擬雙行字幕與原字幕的垂直位置差異，並保留讀音載入前後的文字基線。20、24、32px 的隔離瀏覽器案例均納入測試；其他原生排版仍需驗證。
- 持續逐字輸入時，分析最多等待約 350ms 才發出，不需等整句停止更新；只將仍相符的已完成前段結果套用到目前字幕。實際顯示時間仍受分析速度影響。
- 多個獨立原生字幕視窗目前可能被合併為一個覆蓋層、改變位置；測試環境確認此限制，真實影片發生頻率未知。真實 YouTube 可播放字幕仍需驗收。

## v0.3.4：減少逐字字幕閃爍

- 字幕逐字增加時，以增量方式保留已確認且後方已有內容的假名節點，只更新可能變動的尾段；讀音重新分析完成後再比對差異。若新字幕改寫而非單純追加，或語言標記改變，會清除可能過期的讀音並重新分析。
- YouTube 在同一播放器重建字幕來源時保留覆蓋層。原生字幕節點短暫缺失時最多保留120ms，若字幕未回來就清除；明確停用、隱藏字幕或導航仍立即回復。短暫僅有漢字時顯示無假名原文，最多保留250ms再退回原字幕。
- 已用隔離Edge fixture重現11次逐字更新與原生字幕來源、視窗重建，修正前假名11次被移除，修正後11次均保留同一節點；另測來源語言切換、原生長時間缺字幕與延遲讀音。此測試不代表真實YouTube的所有重建行為。
- 已確認一項未修閱讀限制：窄播放器的雙行字幕可能相對YouTube原本位置出現垂直間距偏差；模擬案例第二行約低12px。特殊排版、多窗口及真實可播放日文CC仍需驗收。

## v0.3.3：字幕可讀性與中日混合

- 假名預設白字深色底，提高在亮色畫面的可讀性；YouTube 字幕原文樣式繼續跟隨原生設定。給覆蓋層預留透明寬度，降低假名將原本一行字幕擠斷的機會。快速變動的直播字幕先立即顯示原文，並合併短時間的重複分析請求，減少積壓。
- CC 先按標點／換行分區，對有明確假名訊號的日文部分標音；中文部分保持原文。處理部分中日連寫、純中文誤標 ja、以及來源標記 zh 的日文字幕。純漢字獨立字幕通常保持原生，因無法單靠字形可靠辨別中日文。
- 中日緊密混寫與人名仍可能模糊：保守策略可能漏掉部分日文，也不能保證所有中文都不會被誤標。使用者可用自訂詞典修正讀音，但不能把不確定的中文當作可靠日文。
- 修正「一回」為「いっかい」，保留使用者自訂詞優先權。「市場」等語境讀音仍可能不符，需另行確認而非強制全域覆寫。
- 付費產品構想擴展為跨語言 CC 字幕外觀自訂：中文、英文、日文等字幕未來都可套用字型、顏色、背景、位置與裝飾。這是遠期方向及獨立互動雛型，沒有實作會員、付費或多語字幕自訂系統；日文假名仍僅處理日文。
- 新增模擬播放器中日混合及讀音回歸；兩名輕量 agents 分別獨立測試字幕語言及21例讀音。仍須以真實可播放日文 CC 的 YouTube 影片驗收。

## v0.3.2：YouTube 字幕樣式與穩定性

- 保持 YouTube 原始字幕視窗負責拖曳，FuriPop 覆蓋層不攔截滑鼠；觀察原字幕視窗的位置變化並同步。已在模擬播放器驗證指標可穿透並跟隨移動，真實 YouTube 影片的原生拖移尚待驗證。
- 日文字幕更換時，先在同一覆蓋層顯示新句原文，分析後直接填入讀音，不再每句切換原字幕與覆蓋層。讀音尚未準備好時不顯示舊讀音；真正關閉字幕、停用或發生錯誤時仍恢復原字幕。保留足夠行高，降低讀音完成時的基線跳動。
- 沿用 YouTube 的字型、字體大小、字重，並同步字幕文字顏色、文字背景及透明度、陰影、字幕視窗背景與透明度。不同字幕視窗或單字使用多種樣式、特殊字幕動畫與排版，仍可能與原版不同。
- 現有的 YouTube 字幕基本設定與可讀性視為免費核心。未來進階付費構想：更多字型風格、小圖案、字幕飾框及更細緻的位置／樣式設定；功能邊界、價格與會員驗證尚未決定，沒有在產品中啟用付費牆。另有獨立互動雛型，僅為預覽，不影響實際影片字幕。
- 隔離瀏覽器測試涵蓋模擬原生拖移、不同字幕尺寸與顏色、背景、透明度、連續換句、舊結果延遲、字幕關閉／停用回復與全螢幕。仍需在真實可播放日文 CC 的影片上驗收。

## v0.3.1：YouTube CC 自動標音

- 日文 CC 使用擴充功能自己的 ruby 覆蓋層，顯示漢字詞上方的平假名，不需跟著字幕移動滑鼠。X 及 YouTube 標題、資訊欄、留言維持懸停方式。
- 字幕新句非同步分析期間先顯示 YouTube 原字幕；只在新句完整分析且覆蓋層就緒後才隱藏原字幕。舊結果、停用、字幕關閉或分析失敗不會留下錯誤讀音或遮住原字幕。

- 已在隔離瀏覽器驗證自動標音、字幕換句、故意延遲舊結果、關閉 CC／停用外掛還原原字幕、全螢幕及控制列互動；真實 YouTube CC 仍待可播放日文字幕的影片驗證。特殊字幕字型、動畫及多視窗排版可能與原版不同。

## v0.3.0：YouTube 日文讀音

## v0.2.0 修正

舊版只會匹配內建百餘詞，因此多數漢字沒有讀音；長句反白只回傳第一個命中詞。
現在使用內附 Kuromoji.js 0.1.2 + IPADIC 詞典分析整段上下文，懸停顯示所在詞的平假名，反白則顯示整句讀音。保留經挑選的次文化詞／繁日異體詞覆寫。

- 推文、回覆與個人簡介可懸停；X 頁面其他唯讀文字可用反白模式。
- 不插入 ruby、不抽換推文 TextNode、不標記已處理節點。以 caret + Range 讀取當下文字、固定浮層顯示；X 更新、SPA 導航、虛擬節點重用後仍按新文字分析。
- 懸停略過連結、按鈕、編輯器；反白可讀包含連結的完整推文。Emoji 與原文維持不變。
- 反白支援滑鼠及鍵盤。浮層會避開視窗邊界；按 Esc、捲動或停用即關閉。非同步過期結果不會重新打開浮層。
- 開關透過 storage.onChanged 同步所有已開啟 X 分頁。
- 完全本機分析，不使用雲端 API、不傳送推文。首次使用才載入詞典，有載入／錯誤提示。

## 自動測試責任與擴大驗證

主要功能驗證由開發代理執行，使用者只需提供補充的語境或體驗回饋。已有統一測試入口：node tests/run.cjs；發布前使用 node tests/run.cjs --all 執行完整16組（瀏覽器組需playwright-core）。分工、案例類型與環境說明見 tests/README.md。

本次擴充：68個語言規則案例、6項一致性檢查、34個不計正確率的語言探索輸入、181組分詞性質案例、250個Worker狀態事件與48組瀏覽器情境。這些數量含確定性組合與情境變形，不能視為真實使用者樣本數或讀音準確率。短中日混合句的判斷仍有已知弱點。

## 安裝／更新

1. 使用 Chrome 116 以上版本，開啟 chrome://extensions/，啟用開發人員模式。
2. 載入未封裝項目，選擇本專案根目錄（manifest.json 所在資料夾）。原有安裝請按重新載入。
3. 重新整理已開啟的 X 分頁；把滑鼠移到「図書館」「新しい」「読みました」等詞，或反白整句。
4. 首次載入需稍候；後續使用共用詞典與有上限的記憶體快取。

權限：storage 儲存開關；offscreen 執行共用 Worker。網域包含 x.com、twitter.com 與 www.youtube.com。其他網站與輸入框尚未注入／支援，舊交接文檔的「任意區域」不代表全網可用。

## 目前架構

content/content.js → runtime message → background.js → engine/offscreen.html → engine/worker.js → vendor/kuromoji/

- Service Worker 只負責建立共用 offscreen document 與轉送請求。
- Offscreen document 管理 Worker 生命週期與逾時；CPU 分詞與詞典解壓均在 Worker。
- Worker 延遲載入單一詞典實例、串行處理請求，快取最多 300 段；分頁另快取 150 段並合併相同未完成請求。
- 單次上限 2000 字，防止巨大反白長文堵塞分析。記憶體快取會在擴充功能／瀏覽器重啟後清除，沒有 IndexedDB 持久快取。
- engine/overrides.js 保留舊版詞庫作為參考；Worker 僅挑選專有詞覆寫，避免「何」「今日」「私」等單字先硬切造成語境誤讀。
- 所有讀音透過 textContent 顯示，沒有把推文當作 HTML 注入。

Kuromoji 的接法依據官方專案：https://github.com/takuyaa/kuromoji.js 。隨附套件及詞典授權見 vendor/kuromoji/LICENSE-2.0.txt 與 NOTICE.md。詞典約 17 MB 壓縮資料，解壓後記憶體用量更高；共用 Worker 避免每個分頁都載一份。

## 驗證與限制

已驗證一般長句、活用、次文化詞、空白／換行、emoji／罕見字的 UTF-16 位置、未知字保留原文；真實 Chrome 驗證懸停、反白、連結保護、Esc 與推文 DOM 不變。隔離 Edge 的 MV3 擴充功能測試已串起完整背景／offscreen／Worker／詞典／內容腳本，並驗證節點重用及跨情境開關同步。

可用 Node.js 18+ 執行 `node tests/tokenizer.cjs` 重跑核心回歸測試，不需 npm install。

這些測試使用本機模擬 X DOM，尚未在登入的真實 X 動態牆手動驗收。X 若改動 tweetText / UserDescription 標記需調整選擇器。單一文字節點以外的詞能映射 Range；已保留明確換行及 Emoji 圖片邊界，仍未全面覆蓋 X 的所有 DOM 結構。

分詞詞典不能保證人名、新詞、繁體中文句子或多音字讀音正確；沒有可靠讀音時保留原文並提示。漢字懸停以詞為單位，並非將每個漢字強制配一個讀音。不為純假名／英文顯示多餘標音。長篇讀音可以在浮窗內捲動。

## ⚠️ 已知技術地雷與踩坑紀錄 (Gotchas & Warnings)

1. **推特 SPA 虛擬 DOM**：
   - 遍歷推文子節點時，必須先 `walk(child)` 完成替換，再給父容器加上 `data-furipop-done="true"` 標記。若順序顛倒會導致遍歷中斷。
2. **文字節點抽換**：
   - 遇到 `<a>`（推特 Hashtag、Mention、短網址）與 Emoji 節點時，必須略過或保護，避免推特點擊連結失效。
3. **Chrome 擴充功能重新載入機制**：
   - 修改 `manifest.json` 或 `content.js` 後，必須在 `chrome://extensions/` 點擊重新整理按鈕，並在推特頁面按 `F5` 才能看到最新代碼效果。
